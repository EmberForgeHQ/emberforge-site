Why Nexus exists

One connection point. Fewer disconnected pieces.

Ember Nexus started with a crosschat problem. Instead of building another one-off fix for one game, the idea expanded into a reusable platform where communities can choose how their existing systems talk to each other.

01 / CROSSCHAT

Route conversation where it belongs.

Planned support includes game-to-game, game-to-Discord, Discord-to-game, cross-game routes, labels, filters, moderation, and loop prevention.

02 / COMMERCE

Connect websites to game shops.

Catalogs, currencies, orders, fulfillment, delivery state, and game-specific adapters are part of the design direction.

03 / AUTOMATION

WHEN → IF → THEN.

Future automation could react to joins, outages, orders, milestones, and other game or community events.

04 / IDENTITY

One community account, many game identities.

The roadmap includes linking Discord and game identities without forcing every game into the same internal shape.

05 / ADAPTERS

Games plug in. Core stays generic.

ARK, Minecraft, Palworld, Conan, and future games should connect through adapters rather than being baked into Nexus Core.

06 / CONTROL

No-code first. API always.

Regular admins should be able to configure common behavior in a dashboard while developers still get serious API access.

Architecture direction

A generic core with game-specific edges.

Phoenix Clan Rising is intended to be the first proving ground, not a permanent hardcoded assumption. Nexus Core should understand organizations, servers, players, events, commands, orders, delivery, health, and credentials in generic terms.

Early roadmap

Design first. Then summon the codebase.

Nexus is intentionally early. The roadmap begins with product definition and threat modeling before the game-independent core and first ARK crosschat adapter are built.

PHASE 0

Product Foundation

Brand, terminology, principles, repository structure, documentation, and security/threat model.

PHASE 1

Nexus Core

Organizations, servers, authentication, event ingestion, heartbeats, status, logging, and versioning.

PHASE 2

ARK Adapter + Crosschat

PCR becomes the first real-world proving ground for ARK ↔ ARK ↔ Discord routing.

PHASE 3

Nexus Dashboard

No-code management for servers, routes, credentials, formatting, permissions, logs, and health.

PHASE 4–6

Identity, Commerce + Automation

Unified player identity, generic commerce, fulfillment, and configurable workflows.

PHASE 7–8

Multi-Game + Productization

More official adapters, SDK direction, external beta, deployment strategy, privacy controls, support, and funding model.

Ember Nexus is not released software and does not have final pricing or a final deployment model. This page describes the current product direction, not a promise that every planned feature ships exactly as written.
