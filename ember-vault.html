Current foundation

The boring parts are doing important work.

Before public beta, Ember Vault is being hardened around the things an economy bot cannot afford to get cute about: isolation, permissions, configuration, data boundaries, and predictable operation.

01 / ISOLATION

Every guild gets its own economy.

Wallets, balances, transactions, cooldowns, rewards, shops, vouchers, redemptions, role income, and settings are scoped to the Discord server that owns them.

02 / CONFIGURATION

Make it yours.

Guilds can configure currency names and symbols, starting balances, manager roles, and transaction log channels.

03 / PERMISSIONS

Delegate without handing over the kingdom.

Ember Vault supports a configurable manager role alongside server owner, Administrator, and Manage Server access.

04 / MARKETPLACE

Shop and fulfillment stay scoped.

Rewards, vouchers, inventory, and redemptions are designed so one server cannot see or manage another server's records.

05 / OPERATIONS

It has its own house now.

Ember Vault runs as its own service with its own service identity and database on EmberForge's application infrastructure.

06 / ROADMAP

Core first. Power later.

Onboarding, admin controls, documentation, support readiness, production hardening, dashboard work, analytics, and automation remain ahead.

Product direction

Useful free. More power when you need it.

Spark and Inferno are the current product direction, but Ember Vault is still pre-beta. Limits and paid features can continue to change before launch as we test what is actually useful and sustainable.
